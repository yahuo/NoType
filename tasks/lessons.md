# Lessons

- 2026-03-26: 火山豆包语音接入前，先确认当前采用的是旧版 `appid/token/cluster` 协议还是新版 `API Key + X-Api-Resource-Id` 协议；不要根据控制台里的“实例ID/名称”去猜 `cluster` 或 `resource_id`。
- 2026-03-26: `MenuBarExtra` 的 accessory app 里不要依赖 SwiftUI `Settings` scene 或同步弹出设置窗口；优先用自管的 `NSWindow`，并把打开动作放到 `DispatchQueue.main.async` 里，等菜单栏弹层收起后再前置窗口。
- 2026-03-26: 从菜单栏面板跳到独立窗口时，先只收起当前 `keyWindow` 对应的菜单栏面板，不要顺手隐藏 `mainWindow`，否则会误伤其他业务窗口。
- 2026-03-26: WebSocket 的 HTTP 预探测结果不能直接当成真实握手结论；如果预探测和原始 HTTP/1.1 或真实 websocket 行为冲突，优先相信后者，不要因为预探测非 101 就提前中止诊断。
- 2026-03-26: Keychain 凭证保存不要用“先删再加”的乐观写法；空值应直接删除，有值优先 `SecItemUpdate`，仅在 `errSecItemNotFound` 时再 `SecItemAdd`，否则很容易把重复项错误直接暴露给用户。
- 2026-03-26: 对有显式 final 包的流式协议，停止录音时不要通过异步 chunk 回调再补发尾包；尾包和 final 必须由同一条停止流程串行发送，否则服务端很容易报“last packet has been received already”。
- 2026-03-26: 回答“当前快捷键/配置是什么”这类运行态问题时，先区分代码默认值和用户本机已保存值；必要时直接读取本地偏好，而不是只看源码默认值。
- 2026-03-26: 改 app 的默认展示模式时，要同时检查 `applicationDidFinishLaunching` 里的 activation policy 是否还在无条件覆盖；否则新默认值会只闪一下就被启动逻辑改回去。
- 2026-03-26: 给菜单栏 app 增加 Dock 图标模式时，不能只切 activation policy；还要定义 Dock 点击后的 reopen 行为，否则用户会看到 Dock 图标但点击没有任何反馈。
- 2026-03-26: 当界面同时维护 `errorMessage` 和 `diagnosticsMessage` 这类并行状态时，新的诊断/成功流程必须主动清掉旧错误，否则用户会看到“当前成功日志 + 历史失败红字”并误判当前结果。
- 2026-03-26: 设置保存里如果某个副作用（如登录启动注册、热键注册）失败，不要整份回滚表单状态；应只恢复失败的那一项，避免把用户刚输入的 `App ID` 等无关字段一起清空。
- 2026-03-26: 非核心的辅助热键失败（如取消热键）不应拖垮主热键注册；主热键能用时应继续保留，只把辅助热键失败作为 warning 暴露出来。
- 2026-03-26: 依赖 App 事件循环/系统目标对象的注册（如 Carbon 全局热键）不要放在 SwiftUI App 的 model init 里做；应等到 `applicationDidFinishLaunching` 之后再初始化，并检查安装事件处理器的返回值。
- 2026-03-27: 全局热键这类强依赖运行时的功能，不能只靠代码审查、build/test 或生命周期推断就宣布修好；必须拿安装版做真实触发验证，或在产品里加可见的运行时注册/触发日志再下结论。
- 2026-03-27: 用户说“提交到 GitHub，创建项目”时，不要默认只做本地 `git init`；先覆盖远程仓库创建、首个提交和默认分支要求，尤其不要擅自用 `main`，应先确认或遵循用户指定的 `master`。
- 2026-03-30: 做产品级重构时，不要在没有明确确认的情况下替换掉用户已经依赖的核心交互主链，比如现有热键方案或语音后端；即使新增了更“原生”的实现，也要先确认是增量并存还是直接替换。
- 2026-03-30: 设计语音 rewrite prompt 时，不要默认只优化成“对人类自然”的书面文本；如果用户主要用它给 AI/编码代理口述任务，prompt 要优先保留步骤、约束、验收项，并在明显列点场景下输出 AI 友好的编号结构。
- 2026-03-30: 提交前必须检查是否把工具运行态或内部规划目录一起带进去了，尤其是 `.superpowers/`、`docs/superpowers/`、`dist/` 这类产物；没有用户明确要求就不要提交。
- 2026-03-30: 改 README 媒体引用时，不要只验证“能不能显示”，还要验证目标渲染器里的对齐效果；Markdown 图片和 HTML `<img>` 在相对路径与居中行为上可能不一致。
- 2026-03-30: 正常 build/install 不要把可再生成的 iconset、icns 或 dist 产物写回并跟踪在仓库里；源图保留在 repo，生成物走临时目录或忽略规则。
- 2026-03-31: 语音 rewrite prompt 不能只要求“更自然”或“对 AI 友好”；必须明确把 transcript 当作待编辑文本而不是给模型的任务，并显式禁止回答问题、执行请求或补充原文没有的新内容。
- 2026-04-07: 给 AI provider 做接入时，不要默认所有厂商都能稳定走同一套 OpenAI 兼容解析；如果用户场景明确涉及 Gemini 这类原生协议差异，优先把 provider 选择显式暴露到设置层，并按 provider 实现和诊断各自的请求/响应链路。
- 2026-04-07: 做 provider 切换时，不要试图“尽量保留”跨 provider 的模型标识；`gpt-*` 和 `gemini-*` 这类 model ID 通常不能跨后端复用，切换 provider 时应主动重置到新 provider 的默认模型，避免把无效配置静默带过去。
- 2026-04-07: 接 Gemini 原生 REST 时，不要假设用户只会输入裸模型名；文档里常见 `models/{model}` 形式，拼接 URL 前必须先把 `models/` 和前导 `/` 规范化掉，否则很容易生成 `/models/models/...` 这种隐蔽 404。
- 2026-04-07: 多 provider 接入不能只拆模型和 URL，不拆凭证；如果 OpenAI-compatible 和 Gemini 共用一个 key 存储槽，provider 切换会立即串用或覆盖对方凭证。至少要按 provider 分开存储，并在切换时切换到对应凭证。
- 2026-04-07: 讨论 macOS 分发方案时，不要默认用户愿意加入付费 Apple Developer Program；先确认预算和是否接受未 notarize 的实验性分发，再决定官网文案、下载路径和发布说明。
- 2026-04-30: 改全局热键到 Fn 这类强运行态功能时，不要只改源码和跑单测就让用户验证；必须重新构建/安装当前 app，并提供可见的 event tap/Input Monitoring 状态或保留旧热键 fallback，避免用户实际还在跑旧安装版或无从判断 Fn 是否被捕获。
- 2026-04-30: 裸 Fn/Globe 会和 macOS Emoji/输入法入口冲突；除非用户明确愿意改系统键盘设置，否则不要把裸 Fn 作为默认主热键。优先使用稳定组合键，并避免为 Fn 引入 Input Monitoring 作为默认权限要求。
- [2026-08-25] 用户指出 HUD 两侧录音按钮都不可点击后，仍先按单个 X 的修复方向收敛 → 先确认同一交互面上所有控件的运行态可用性；若用户选择快捷键主链，应移除不可用按钮而不是保留误导性控件。
- [2026-08-25] 移除 HUD 两侧按钮时忽略了按钮原本撑起的 36pt 高度，导致胶囊视觉变窄 → 删除布局控件前先记录其对父布局的隐式尺寸贡献，并显式保留原有视觉尺寸。
- [2026-08-25] Herdr 端到端测试的准备命令已经等待超时，仍宣称测试 pane 就绪并让用户按三次空格 → 要求用户执行物理操作前，必须先读取目标 pane，确认预置文本、前台等待进程和焦点三项均已就绪。
- [2026-08-25] 把标准输入框的 `AXValue + Cmd+A` 整框翻译直接用于终端/TUI，导致 Herdr 命令行读取失败时静默无响应 → 新增跨应用输入能力前先验证目标控件的 AX 语义；不支持时必须给出可见反馈，不能静默返回。
- [2026-08-25] 看到 Herdr 无响应就直接归因为终端特例，未先用 Codex 富文本输入框做反例验证 → 判定应用特例前至少比较普通文本框、富文本框和终端三类目标，并为每个静默 guard 提供阶段证据。
- [2026-08-25] 用户说明 Codex 中三空格曾经灵敏、现在只是很难触发时，不能继续把问题当成静态控件不兼容 → 对间歇性回归先核对代码与运行进程时间线，并区分按键检测和 AX 文本读取两个阶段。
- [2026-08-25] 修复 Codex 的 AX 更新延迟后仍未明确终端输入的能力边界，iTerm2 和 Ghostty 都无法走标准输入框链路 → 把 PTY 屏幕缓冲区与可编辑 AX 文本框视为两类目标，终端支持必须单独设计和验证。
- [2026-09-07] 选词长文翻译复用听写改写的 10 秒总超时，导致流式输出尚未完成就中断 → 阅读型翻译必须使用独立的总时限和网络无响应时限，并用延迟流测试覆盖超过旧时限仍成功、真正超时和主动取消。

- [2026-09-07] 将 `NWListener.newConnectionLimit = 16` 当作并发连接限制，导致累计接受 16 个 socket 后监听器暂停、网页翻译卡住 → 该属性是累计接收额度，关闭连接不会补回；并发上限应按存活连接计数，浏览器会话复用长连接，并回归连续超过 16 次连接和同连接多批请求。

- [2026-09-07] iframe 翻译复用正文脚本时也复制了进度浮层，导致多个框架各自遮挡内容 → 页面级进度与关闭入口只由顶层文档显示；跨域、嵌套和动态 iframe 回归须检查整页仅一个浮层，并验证关闭清除所有框架译文。

- [2026-09-09] 仅凭流式转写可用、合成录音结果和耗时改善就切换默认识别路径，随后收到真人识别质量下降反馈 → 默认语音接口切换前，应使用同一段真人录音对照整段与流式路径的语义准确度和文字整理效果；性能测试不能替代识别质量验收，质量未验证的客户端留在实验测试中。

- [2026-09-09] 接入 Codex realtime 双向语音后，工具 delegation 仍返回不支持，用户发现联网搜索缺失、体验不等同于 Codex Voice → 连续对话、打断与工具委托应分别验收；完整助手还需接入 Codex 代理工具层，未接前明确仅支持语音聊天，临时会话不保存历史也须单独验证。

- [2026-09-09] 退出语音漏匹配“结束会话”，补齐后又在识别到结束指令时立即断开，截断 Neo 的告别 → 结束指令覆盖常见同义表达及转写标点，防止否定句和解释请求误退出；语音退出应保持浮窗与音频流，等告别回复完成且尾音播放结束后再关闭，手动关闭仍立即执行；回归覆盖用户转写触发、回复中途停顿、播放收尾、连接释放、浮窗隐藏与重新待命。

- [2026-09-09] 把临时语音会话与关闭已有记忆绑定，导致 Neo 无法基于用户的 Codex 上下文讨论 → 会话持久化、读取已有记忆、生成新记忆分别控制；需要个人上下文时开启已有记忆读取，保留临时会话并关闭自动生成，记忆问题交给 Codex 执行层；分别验收启动摘要、按需检索和不产生会话历史。

- [2026-09-09] Neo 设置说明过长，用户要求精简 → 每行只说明一项操作或能力，省略连接过程和重复的实现细节。

- [2026-09-09] Neo 验收探针使用 medium，生产执行层却继承本机 max，单独验证播报掩盖了用户对话中的长等待 → 性能验收须复用实际模型与思考配置，覆盖用户音频、委托处理、结果排队和首段音频，并只记录阶段耗时，不保存对话正文。

- [2026-09-09] Neo 页自动保存且隐藏 Save，与同窗口其他设置页不一致 → 设置页统一显式保存，草稿与运行配置分开；菜单快捷开关仍即时生效，但不得顺带保存其他草稿。

- [2026-09-09] Neo 执行模型候选包含用户不需要的 GPT-5.5 → 当前仅提供 Luna、Terra、Sol、Astra；移除候选时保留旧配置回退，避免丢失其他设置。

- [2026-09-10] Neo 全局助手把工作目录设在应用数据目录，导致对话带入 NoType 目录语境 → 默认使用用户主目录，并同时核验子进程 cwd 和临时会话 cwd。

- [2026-09-10] 仅凭最终收到新回复就判定语音打断成功，漏掉插话后仍播报旧内容 → 分别验证首次停声耗时与新回复内容；本地先暂停播放，服务端确认用户输入后再通知模型丢弃旧回答；分段转写完成不等于用户停声，恢复播放前还要检查麦克风，覆盖杂音恢复、迟到事件和告别收尾。

- [2026-09-10] Neo 将 WebRTC disconnected 立即当作失败，建连阶段偶发断开也直接报错，媒体错误又被统一成“连接已断开” → HTTP 会话创建和音频通道就绪分别验证；disconnected 先等待短暂恢复，尚未开始对话或执行任务时只自动重试一次，记录传输状态与错误来源，覆盖失败恢复、重试上限、取消和真实连接收尾。
